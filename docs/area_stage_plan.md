# エリア内ステージ制 設計メモ

## 目的

- エリア内を複数ステージに分け、報告書や探索の流れに段階感を持たせる。
- ステージごとに通常敵・ボス・報告文を分け、物語の変化を付けやすくする。
- いきなり全体へ広げず、まずは小さく検討して実装リスクを見極める。

## 現状整理

- 現在の進行管理はエリア単位。
- エリア選択は `party.selectedArea`、クリア実績は `state.areaClears[areaId]` で管理している。
- 実際の敵出現も `AREAS[areaId].monsters` と `AREAS[areaId].boss` を使う構造で、ステージ番号の概念は未実装。
- 進行バーの `探索中 / 危険区域 / ボス接近 / 帰還準備` は表示用であり、内部ステージではない。

## 基本方針

- エリアIDは維持する。
- 敵IDは安易に変更しない。
- まずはエリアの中に `stages` 相当の定義を持たせる方向で考える。
- ステージごとに通常敵・ボス・報告文を分けられるようにする。
- 今回は設計メモのみ。まだ本実装はしない。

補足:
- 草原・森に加えて、沼・遺跡・峡谷・氷原も各3小区画で実装済み。
- 旧 `swamp` / `ruins` / `canyon` / `glacier` は互換用に残し、派遣先一覧からは外している。
- 旧セーブの `selectedArea` は新しい先頭小区画へ寄せ、旧クリア実績は新小区画側へ同期する。
- `volcano` の解放条件は氷原最終小区画へ接続済み。
- 未解放派遣先は一覧表示のみ行い、グレー表示・選択不可で条件文言は出さない。

## まず試す対象範囲

- 始まりの草原
- 月影の森

この2エリアだけで、ステージ制の手触りと必要な保存項目を確認する。

補足:
- 草原3派遣先の表示名は、別エリア追加ではなく同じ「始まりの平原」内の小区画に見せる方針とする。
- 現在の表示名は `始まりの平原（村周辺）` / `始まりの平原（石畳の街道）` / `始まりの平原（ゴブリンの巣）`。
- 月影の森3派遣先の表示名も、同じ「月影の森」内の小区画に見せる方針とする。
- 現在の表示名は `月影の森（遠吠えの道）` / `月影の森（苔むす獣道）` / `月影の森（巨獣の縄張り）`。

- 位置づけ: 街道外れの浅い探索

- ボス: なし
- 報告文の方向: 草むらの揺れ、足慣らし、不穏さはまだ薄い

### Stage 2

- 位置づけ: 少し奥へ入る区間
- 通常敵: `slime`, `goblin`
- ボス: なし

### Stage 3

- 位置づけ: 草原奥の危険域
- 通常敵: `goblin`
- ボス: `goblinChief`
- 報告文の方向: 待ち伏せ、統率された気配、帰還後に印象が残る締め

## セーブデータへの影響

- エリアIDを維持するだけなら、既存のエリア選択や解放条件との衝突は小さい。
- ただし「どのステージまで進んだか」を保存する場合は、新しい保存項目が必要になる。
- 暫定案としては、保存項目を増やさずにエリア内で固定3ステージ進行を組む方法もある。
- 本格的に「小隊ごとのステージ到達状況」を持つ場合は、save / load / migrate / reset の対応が必要。

## 実装時の注意

- 既存の `selectedArea` を壊さず、内部的にステージ解決する形を優先する。
- まずは敵出現テーブルの切り替えだけで成立する形を目指す。
- ボス接近表示や報告書文面が、ステージ構造と食い違わないようにする。
- 図鑑やドロップ表示は敵ID基準なので、敵ID変更は避ける。
- 既存のエリア解放条件 `unlockAfter` はそのまま維持する。
- いきなり全エリアへ広げず、始まりの草原だけで先に確認してから月影の森へ広げる。

## 未決事項

- ステージ進行を全体共有にするか、小隊ごとに持つか。
- ステージ番号をUIに見せるか、内部管理だけに留めるか。
- 報告文を `AREAS` 側で持つか、別構造で持つか。
- 各ステージで戦闘回数を固定するか、今の進行率表示と連動させるか。
- ボスを毎回最終ステージ固定にするか、条件式にするか。
- 既存エリアを将来3ステージ以上に広げる前提で定義するか。
