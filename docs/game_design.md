## 装備・保管庫・合成仕様追記

### 装備個体管理

- 装備はベース定義（id / name / slot / rarity / 各種能力値）に加えて、個体ごとの差分を持てる
- 個体差として扱う主な項目は `plus` / `enhance` / `options` / `optionCandidates` / `fixedOptions` / `locked`
- 個体差のない装備は装備スロット上ではID文字列で保持できる
- 個体差のある装備は装備スロット上でも装備オブジェクトのまま保持する
- 保管庫に入る装備は個体単位で正規化される

### storageUid

- 保管庫装備は各個体に `storageUid` を持つ
- `storageUid` は保管庫内の同名装備を区別するための個体識別子
- 合成中の育成対象選択、素材選択、連続合成継続は `storageUid` を基準に管理する
- 旧セーブなど `storageUid` を持たない装備はロード時に補完する

### 保管庫表示

- 保管庫は装備一覧と装備中一覧を合わせて表示する
- フィルターは `all / weapon / armor / accessory / artifact`
- 並び替えは `new / rarity / type / name`
- 保護中装備は売却不可
- 装備中装備は「装備中」表示が付き、必要に応じて保管庫画面から装備解除できる

### 通常時はグループ表示

- 通常の保管庫表示は同系統装備をグループ化してまとめて表示する
- 個体差のない同一装備は1行に集約し、複数所持時は件数表示する
- ただし以下は個別扱いとしてグループを分ける
- `options` を持つ装備
- `optionCandidates` を持つ装備
- `fixedOptions` を持つ装備
- `plus` / `enhance` が異なる装備
- 保護状態が異なる装備
- 装備中装備

### 合成中は個体表示

- 装備合成モード中はグループ化せず、対象候補・素材候補を個体単位で表示する
- チェックボックス操作はすべて個体単位で行う
- 同名同性能でも `storageUid` ごとに別個体として選択する

### 装備合成 STEP1 / STEP2

- STEP1 は育成対象を1本選ぶ段階
- STEP1 では合成対象にできる装備だけを個体表示する
- 育成対象に選べるのは、保管庫内にある装備で、装備中ではなく、アーティファクトではなく、`enhance` がなく、`plus` が20未満の装備
- STEP2 は素材を選ぶ段階
- STEP2 では STEP1 で選んだ育成対象と同じ `id` の装備だけを素材候補として個体表示する
- 素材候補は保護中ではないこと、装備中ではないこと、アーティファクトではないこと、`enhance` がないことが条件

### 育成対象

- 合成対象として選ばれた装備を育成対象と呼ぶ
- 育成対象は `storageUid` 単位で保持する
- 画面上部に育成対象プレビューを固定表示する
- 育成対象は「変更」操作で解除して STEP1 に戻れる
- 合成成功後も同じ個体を育成対象として保持する

### 素材選択

- 素材は育成対象と同じ `id` の装備から選ぶ
- 素材選択は複数選択式
- 必要数は育成対象の `plus` に応じて変化する
- `plus` 0 から 9 までは3本
- `plus` 10 以上は5本
- 必要数に満たない場合は合成実行不可

### 連続合成

- 合成成功後、合成モード自体は解除しない
- 育成対象は維持する
- 消費した素材は保管庫から削除する
- 素材選択だけをクリアして、同じ育成対象で次の素材選択に進める
- このため同一個体を連続して `plus` 強化できる

### options / optionCandidates / fixedOptions

- `options` は現在有効な装備OP本体
- 能力計算で参照されるのは `options`
- `optionCandidates` は成長候補OP
- 候補表示時は「成長候補」として保管庫に表示する
- `fixedOptions` は固定済み候補を表現するための予約領域として保持される
- 現状実装では候補確定時に `fixedOptions` へ移すのではなく、`options` に直接追加している
- 候補生成時の重複除外では `options` / `optionCandidates` / `fixedOptions` の全てを参照する

### +3 / +6 / +9 候補生成

- 合成で `plus` が上がった直後に節目判定を行う
- 節目は `+3` / `+6` / `+9`
- 節目に到達した場合、空きOP枠ぶんだけ候補を生成する
- OP枠上限は3
- 空き枠数は `3 - options数 - fixedOptions数`
- 候補生成時は `options` / `optionCandidates` / `fixedOptions` に含まれるOPを除外して抽選する
- 候補は `optionCandidates` に追加される

### 候補OP固定

- 候補OPは保管庫から個別に確定できる
- 確定操作は候補ボタン押下で行う
- 確定時は `optionCandidates` に含まれる指定候補を検証する
- 確定可能なのは現在の `options` 数が3未満のとき
- 確定した候補は `options` に `Lv1` で追加する
- 確定後、その装備の `optionCandidates` は空にする
- 現状の固定処理は `fixedOptions` へ移す方式ではなく、`options` へ直接反映する方式

### セーブ書き出し / 読み込み

- 通常セーブはローカルストレージに保存する
- セーブ書き出しは現在のローカルセーブJSONをそのままファイル保存する
- セーブ読み込みはJSONファイルを読み込み、最低限の形式確認後にローカルストレージへ保存して再読み込みする
- 形式確認では少なくとも `parties` 配列を持つことを確認する
- ロード時は旧バージョンキーも参照しつつ、必要な整形と移行処理を行う
- 移行処理では保管庫装備の `storageUid` 補完、記録系整形、資金系整形、既存装備記録反映を行う
