# 派遣ギルド！ マスター設計書

## 1. この文書の目的

この文書は、現在の派遣ギルド！について「何を目指すゲームか」「今どこまで実装されているか」「今後どこを伸ばすか」「何をやってはいけないか」を1ファイルで共有するための共通設計書である。

派遣ギルド！は、戦闘そのものを派手に操作するゲームではない。プレイヤーはギルドマスターとして小隊を派遣し、帰還を待ち、報告を読み、少しずつギルドの実態と世界の陰りを見ていく。実装判断もUI判断も、この軸から外れてはいけない。

## 2. コンセプト

派遣ギルド！は、次の感触を核にしたゲームである。

- 派遣を眺めるゲーム
- 帰還を待つゲーム
- 報告書を読むゲーム
- 暗い
- 静か
- 少し不穏

見た目と空気感は、羊皮紙、真鍮、暗木、古いTRPGやWizardry系の手触りを基準にする。ネオン、サイバー、過剰に大げさな演出、叫び調のログは世界観から外れるため採用しない。

戦闘ログも同様で、熱血ではなく記録文として読む感触を優先する。良い表現は「誰が前に出た」「誰が誰をかばった」のような静かな報告文であり、感情を煽るだけの派手な叫びではない。

## 3. 絶対ルール

現在の設計で、演出と進行に関する禁止事項は明確である。

- 未来情報を表示しない
- 派遣開始時点で最終結果を見せない
- ログ進行とHP表示を同期させる
- 死亡者は会話させない
- 死亡者は行動させない
- 冒険開始直後に赤表示を出さない

これらは単なるUI調整ではなく、ゲーム全体の読み味を守るための根本ルールである。

## 4. 現在実装済みの全体像

### 4.1 パーティ

小隊ベースで編成と派遣を扱う構造が前提になっている。キャラクター詳細は「ステータス / 装備 / スキル」のタブ式で整理済みで、小隊メンバー名を押すと詳細を開閉できる。同じキャラを再度押すと閉じる動作もあり、詳細側には専用の閉じるボタンがある。以前の小隊カード右上の閉じるボタンは削除済みで、情報の主導権はキャラ詳細側に寄せている。

### 4.2 派遣

派遣は本作の中心であり、出発して待ち、帰還結果を受け取る流れが成立している。冒険時間は `area.durationMs` を基準に計算され、派遣先表示と実際の `endsAt` が同じ計算系を使う。近道やセット装備による時間短縮効果も共通計算へ接続済みで、同名の短縮効果は重複しない方針で揃えられている。

帰還時の納品通知も実装済みで、右下に最大4件まで縦積み表示される。複数小隊が同時に帰還しても通知を上書きしない。

### 4.3 戦闘

このゲームに戦闘は存在するが、主役ではない。戦闘は派遣の結果を支える内部処理であり、ログで読む体験を優先する。現行方針として、防御、かばう、回復、蘇生などの役割があり、戦士・神官・盗賊・魔法使いの職能が分かれている。

また、スキルのON/OFF UIは実装済みで、戦闘への反映確認を継続課題として持っている。

### 4.4 スキル

職業スキルの枠組みは存在し、戦士、神官、盗賊、魔法使いごとに方向性が明確である。

- 戦士：防御、かばう、挑発、鉄壁、捨て身、反撃
- 神官：ヒール、ミドルヒール、状態回復、リザレクト、神の加護
- 盗賊：近道、宝箱発見、罠解除、奇襲
- 魔法使い：火球、雷撃、氷槍、魔力探知、魔力集中

スキル説明UIは今後、「スキル名 / 効果量 / 制限」の定型フォーマットへ統一する予定である。

### 4.5 状態異常

状態異常は名前や方向性としては意識されているが、本実装はまだ慎重扱いである。戦闘処理の重さに直結するため、現時点では拡張候補であり、完成済み機能としては扱わない。

### 4.6 装備

装備は、単なる固定マスタではなく個体差を持つ設計が入っている。個体差として `plus`、`enhance`、`options`、`optionCandidates`、`locked` を持てる。個体管理が必要な装備はオブジェクトとして保持し、保管庫では個体単位で正規化される。

装備のレアリティや種別に加え、セット装備、遺物、強化、保護の概念が存在する。SET装備は実装済みで、装備名に `(S)` を付けて表示し、真鍮系の専用表示テーマを持つ。

### 4.7 合成

合成は同一装備を素材にした強化フローとして実装方針が固まっている。STEP1で育成対象を1本選び、STEP2で同じ `id` の素材を複数選択する。必要本数は `plus` に応じて変わり、`plus` 0から9は3本、10以上は5本である。

育成対象は `storageUid` 単位で保持し、合成成功後も解除されず、そのまま連続合成に入れる。これにより同一個体を続けて育成できる。

### 4.8 セット装備

SET装備は実装済みで、現状では「旅人一式」が確認されている。効果は冒険時間 -10%、LUC +10で、同一キャラが3点装備したときのみ発動する。小隊内で分散装備しても発動せず、同名効果は小隊内で1回のみ有効である。

### 4.9 保管庫

保管庫は個体管理の中心であり、`storageUid` によって同名装備も区別する。通常時は同系統装備をグループ表示し、個体差のあるもの、装備中のもの、保護状態の違うものは別扱いにする。合成中だけは個体表示に切り替え、素材選択や育成対象選択を正確に行う。

保護中装備は売却不可であり、装備中の装備には装備中表示を付ける。

### 4.10 図録

図録は実装対象として方向が定まっている。敵図録には出現場所、ドロップ、討伐数、BOSSタグを持たせる。装備図録は武器、防具、装飾、遺物の流れで整理する方針である。

### 4.11 世界情勢

世界情勢や異聞録、イベントのような外側の物語要素は候補として意識されているが、現時点では中核実装より後段で扱う。主軸はあくまで派遣、待機、帰還報告である。

### 4.12 UI

UIは一覧性と静けさを重視する。ステータス表は列見出し方式で、基礎 / 装備 / OP をヘッダ表示し、各行へ同じ語を繰り返さない。総値横は実線、基礎 / 装備 / OP 間は破線で整理し、状態異常、耐性・装備効果、セット装備は簡素表示に寄せる。

保管庫UIは整理途中だが、装備保管数・保護数は左側、操作群は右寄せ、小パネル型の整理導線という方針がある。全体CSSに波及する大きな表示制御変更は避ける。

## 5. 現在の戦闘仕様

現時点で読み取れる戦闘仕様は、派遣結果を読みやすく保つための軽量な役割戦闘である。

- HPを持ち、ログ進行と同期して増減を見せる
- 防御役、回復役、支援役、攻撃役の役割分担がある
- かばう、防御、回復、蘇生のような行動が存在する
- 死亡者はその後の会話や行動に参加しない
- 盗賊系スキルとして近道、宝箱発見、罠解除がある
- 罠解除は DEX を使う計算で、盗賊補正が入る
- スキルON/OFFの概念があり、使用可否を戦闘に反映する前提で設計されている

細かな戦闘式や全スキル挙動は今後も調整余地があるが、少なくとも「ログを読む派遣ゲームの戦闘」であることが第一条件である。

## 6. 現在の装備仕様

装備仕様は、保管、強化、表示を含めた個体管理前提で整理されている。

- rarity を持つ
- 武器、防具、装飾、遺物などの枠がある
- SET装備を持てる
- 遺物は通常装備と別格の扱いを受ける
- 合成による `plus` 強化がある
- 装備OPとして `options` を持つ
- 成長候補OPとして `optionCandidates` を持つ
- 保護状態を持てる
- 保管庫では `storageUid` により個体識別する

合成で `plus` が節目に達したときは、`+3 / +6 / +9` で空きOP枠に応じた候補OPを生成する。OPの上限は3で、確定した候補は `options` に `Lv1` として入る。未使用の `fixedOptions` は予約枠であり、現行ロジックでは使わない。

## 7. ドロップ・探索まわりの仕様

本作の報酬体験は、戦闘演出より探索結果の読後感を重視する。

### 7.1 探索スキル

盗賊系スキルにより、次のような探索補助がある。

- 近道：帰還時間短縮
- 宝箱発見：追加抽選 +1
- 罠解除：DEX基準の判定

### 7.2 図録上の記録

敵図録では、出現場所、ドロップ、討伐数、BOSSタグを記録対象とする。装備図録は入手品の蓄積を俯瞰する用途を持つ。

### 7.3 保管と売却の前提

装備は保管庫に集まり、保護中の装備は売却不可である。通常時はグループ表示、合成時は個体表示とし、プレイヤーが誤って重要装備を失わないことを優先する。

## 8. UI方針

UIは常に世界観の延長線上で考える。

- 羊皮紙
- 暗木
- 真鍮
- 古い記録帳のような静かな整理
- 派手演出禁止
- ネオン禁止
- サイバー調禁止

また、操作性の方針も明確である。

- 情報は整理して見せる
- 進行更新のたびに全体を無駄に再生成しない
- 開閉や選択状態を不用意に壊さない
- 小さなUI改善でも全体CSSへの波及を避ける
- 表示の豪華さより、読みやすさと落ち着きを優先する

## 9. 今後やる予定

現行資料から確認できる今後候補は、実装済み土台を壊さずに深める方向が中心である。

### 9.1 優先度高

- スキルON/OFFが戦闘へ正しく反映されているかの継続確認
- スキル説明フォーマットの統一
- レベルアップ習得の実装
- 保管庫UIの整理継続
- 進行更新時に不要な再描画を避ける改善

### 9.2 中期候補

- エリア個性
- 異聞録
- イベント
- ギルド強化
- 状態異常追加

これらは「戦うゲーム」に寄せるためではなく、派遣と帰還報告の密度を上げるために扱う。

## 10. 保留事項

以下は大工事または戦闘処理の肥大化につながるため、現時点では保留または慎重扱いである。

- 状態異常の本実装
- 装備4枠化
- STR / INT の分離
- 属性武器

特に装備4枠化は、セーブ、装備UI、ドロップ、合成に広く影響する。STR / INT 分離も戦闘式と装備設計の再整理が必要になるため、安易に着手しない。

## 11. Codex運用ルール

このプロジェクトでCodexを使うときのルールは明確である。

- まず原因確認を優先する
- 確認だけ、読み取りのみを多用して慎重に進める
- 変更は最小にする
- GitHub push は行わない
- 勝手なUI全面変更をしない
- 勝手な世界観変更をしない
- 大規模変更をしない
- 画像生成をしない
- 最後の報告は簡潔にまとめる

今回のように資料を統合するときも、実装の意図を勝手に塗り替えず、既存方針を読める形に整理することを優先する。

## 12. このゲームでやってはいけないこと

派遣ギルド！は、雰囲気と読み味の一貫性が非常に重要である。以下は明確に避ける。

- 戦闘主役のゲームへ寄せること
- 帰還待ちより即時爽快感を優先すること
- ネオン、サイバー、過剰演出で世界観を壊すこと
- 未来情報を見せて待つ楽しみを潰すこと
- 死亡者を平然と会話・行動させること
- UIを派手にして記録物らしさを失うこと
- システムの土台を壊す大規模変更を安易に入れること

本作は、派手な勝利演出より、静かな帰還報告の余韻を大事にするゲームである。この軸を守ることが、今後の追加実装でも最優先になる。
